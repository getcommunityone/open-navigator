# Development docs hygiene

**Issue:** [#721](https://github.com/getcommunityone/open-navigator/issues/721)  
**Status:** approved design (2026-11-22)

## Problem

`web_docs/docs/development/` holds ~93 flat pages. The Developers sidebar primarily dumps the whole folder via `{ type: 'autogenerated', dirName: 'development' }`, so wrong/outdated pages sit next to current guides and look equally authoritative. Agents also lack a standing rule to update the matching Guide when behavior changes.

We still **publish new** designs and plans. We do **not** archive a page just because its issue shipped.

## Decision

**Archive = wrong or misleading**, not “already shipped.”

| Nav bucket | Meaning |
|---|---|
| **Guides & decisions** | Current truth: walkthroughs, contracts, ADRs, operator hubs |
| **Working notes** | In-flight `*-design.md` / `*-plan.md` (and similar) for open work — still published |
| **Archive** | Pages that teach the wrong stack or story — still in the site under Archive, not mixed with Guides |

Shipped-but-accurate plans may stay listed, fold into a Guide, or remain as history next to the Guide. They are **not** mass-moved to Archive on merge.

## Sidebar

Replace reliance on a single autogenerated dump of all of `development/` as the primary Developers nav.

- **Guides & decisions** — curated list (and/or a small subfolder later if needed).
- **Working notes** — curated in-flight designs/plans (keep publishing here).
- **Archive** — pages under `web_docs/docs/development/archive/` (after `git mv`), exposed as an Archive category (autogenerated from that dir or an explicit list).

Relative links that break after `git mv` are fixed in the same PR or noted as follow-ups.

## Wave 1 (content)

Move only pages that are **clearly wrong** into `development/archive/`. Minimum candidates (plan may extend after a short inventory):

- Pages that present `website/docs` or `frontend/src` as the live layout
- Snapshot / migration notes that contradict today’s `web_app/` + `web_docs/` + `packages/` world (e.g. `docs-migration`, `react-refactoring`, `dashboard-redesign`, `integration-status`, and similar `openstates-integration`-class docs)

Do **not** rewrite every body in wave 1. Do **not** archive every completed `*-plan.md`.

## AGENTS.md — Docs with the change

Add a standing section **Docs with the change**:

- If a change alters behavior, contracts, operator UI, or data grain, the **same PR** updates or adds the governed page under `web_docs/docs/`.
- Issue **Done when** / PR body name that doc.
- If you find a page that is **wrong**, fix it in place or move it to Archive in that PR; if the rewrite is out of scope, open an `action-item` and link it (do not leave “TODO: fix docs” only in the PR).
- New designs/plans continue to land under `web_docs/docs/development/` and may appear under Working notes until the work is done.

`CLAUDE.md` already requires docs under `web_docs/docs/`; this rule adds the **update-with-the-change** duty and the Archive criterion.

## Out of scope

- Full rewrite of mixed hubs (e.g. leftover Ollama body under AI policy analysis) — separate `action-item` if needed
- Pruning all of `guides/hackathon/`
- CI that fails on every stale path regex (optional later)
- Treating `cleanup-roadmap.md` (`scripts/ → packages/`) as this hygiene effort
